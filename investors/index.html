The investment thesis

A new infrastructure layer for software that can act.

The shift from AI that generates outputs to AI that takes delegated actions creates infrastructure requirements below the application layer. Agents need to prove who they are, operate within explicit authority, access data under defined rights, coordinate with other agents and account for value exchanged.

01 · EXECUTION

Agent execution environment

Protocol design for deterministic agent workloads and verifiable state transitions, with a Cosmos SDK foundation described in the current technical roadmap.

02 · DATA OWNERSHIP

Data Capsules

A proposed layer for encrypted, portable data and model assets, with ownership and governance mechanisms intended for autonomous systems.

03 · COORDINATION

Agent coordination mesh

A planned messaging and coordination layer for agents that need to discover, communicate and coordinate multi-step workflows.

04 · SETTLEMENT

Machine-to-machine value

A settlement design intended to support frequent, machine-readable transactions between agents, services and infrastructure providers.

05 · TRUST

Identity and verification

Protocol direction for verifiable identities, permission controls and auditable agent actions. Specific implementation and security claims are subject to technical diligence.

06 · ECOSYSTEM

Developer and validator ecosystem

A phased roadmap covering core modules, private and public testnets, validator participation and a planned mainnet launch.

Why AI needs an infrastructure layer

More capable AI needs trusted ways to take action.

The value of autonomous agents will depend on more than model intelligence. Agents that interact with customers, software, businesses and each other need dependable infrastructure for identity, permissions, data, execution and exchange.

01 · IDENTITY & AUTHORITY

Know which agent is acting

Establish agent identity and delegated authority so an agent's actions can be associated with the person, organisation or system that authorised them.

02 · DATA RIGHTS

Keep data access intentional

Give agents a design path to access permitted data and digital assets while respecting ownership, privacy and usage rules. Data Capsules are a proposed component of this approach.

03 · EXECUTION

Make actions verifiable

Support controlled workloads and auditable state changes, rather than relying only on opaque application-to-application hand-offs. The Agent VM remains a planned protocol component.

04 · COORDINATION

Let agents work together

Provide a protocol direction for discovery, messaging and coordination across multi-agent workflows, services and infrastructure providers.

05 · SETTLEMENT

Enable machine-to-machine exchange

Design for agents and services to account for access, compute, APIs and digital goods, with settlement mechanisms appropriate to autonomous commerce.

06 · ACCOUNTABILITY

Make actions easier to audit

Connect identity, permissions and execution records so enterprises and users can inspect how delegated actions occurred and where controls apply.

These are protocol design goals and roadmap areas, not claims that a production network or all listed capabilities are already live.
